15. Acessibilidade Web (a11y) Avançada

No Módulo 7 você viu o básico de HTML semântico e acessibilidade. Agora vamos aprofundar em contraste, navegação por teclado, ARIA e formulários acessíveis — o suficiente para deixar suas páginas utilizáveis por muito mais gente.

- Contraste de Cores

O WCAG (guia oficial de acessibilidade web) recomenda uma razão de contraste mínima entre texto e fundo:

  • 4.5:1 — texto normal
  • 3:1 — texto grande (18px+ em negrito, ou 24px+)
/* Ruim: cinza claro sobre branco, contraste baixo */
.texto-fraco { color: #bbbbbb; background: #ffffff; }

/* Bom: contraste adequado */
.texto-legivel { color: #333333; background: #ffffff; }

Ferramentas como o "Contrast Checker" (buscar online) calculam essa razão automaticamente a partir dos códigos de cor.

- Navegação por Teclado

/* NUNCA faça isso — remove o indicador de foco para todo mundo */
*:focus { outline: none; }

/* Faça isso — um foco visível e estilizado */
*:focus-visible {
    outline: 3px solid #0ea5b7;
    outline-offset: 2px;
}

Pessoas que navegam com teclado (Tab, Shift+Tab, Enter) dependem do indicador de foco para saber onde estão na página. Remover o outline sem substituí-lo é um dos erros de acessibilidade mais comuns — e mais graves.

- ARIA: Quando o HTML Semântico Não Basta

<div role="alert">Formulário enviado com sucesso!</div>

<button aria-expanded="false" aria-controls="menu-mobile">
  Menu
</button>
<ul id="menu-mobile" hidden>...</ul>
  • role="alert" — leitores de tela anunciam a mudança imediatamente
  • aria-expanded — informa se um menu/acordeão está aberto ou fechado
  • aria-label — nomeia um elemento sem texto visível
Regra de ouro do ARIA
"Nenhum ARIA é melhor que ARIA errado." Sempre prefira uma tag HTML semântica nativa (<button>, <nav>) a recriar o comportamento com <div role="button"> — o navegador já cuida do teclado e do foco de graça nas tags nativas.

- Formulários Acessíveis

<label for="email">E-mail</label>
<input type="email" id="email" name="email" required
       aria-describedby="email-ajuda">
<span id="email-ajuda">Usaremos apenas para login.</span>

O atributo for no <label> precisa bater com o id do input — isso permite que clicar no texto do label foque o campo, e que leitores de tela anunciem o nome do campo corretamente.

- Testando sua Página

  • Navegue pela página inteira usando só o Tab do teclado — dá para chegar em tudo?
  • Use as ferramentas de auditoria de acessibilidade já embutidas no navegador (aba "Lighthouse" ou "Accessibility" do DevTools)
  • Aumente o zoom do navegador para 200% — o layout continua funcional?
Acessibilidade não é "só para alguns"
Contraste bom ajuda quem está no sol forte. Navegação por teclado ajuda quem usa o celular com uma mão só. Boas práticas de a11y melhoram a experiência de todo mundo, não apenas de pessoas com deficiência.

- Resumo do Módulo

  • Contraste mínimo de 4.5:1 para texto normal, segundo o WCAG
  • Nunca remova o outline de foco sem um substituto visível
  • ARIA complementa o HTML semântico, mas nunca substitui uma tag nativa disponível
  • <label for> conectado ao id do input é essencial em formulários
