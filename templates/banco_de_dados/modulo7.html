7. GROUP BY e Agregações

As funções de agregação calculam valores sobre um conjunto de linhas. Com GROUP BY você agrupa resultados para gerar relatórios poderosos.

- Funções de Agregação

  • COUNT(*) — conta o número de linhas
  • SUM(coluna) — soma os valores
  • AVG(coluna) — calcula a média
  • MAX(coluna) — maior valor  ·  MIN(coluna) — menor valor
SELECT
    COUNT(*)   AS total_clientes,
    SUM(saldo) AS saldo_total,
    AVG(saldo) AS saldo_medio,
    MAX(saldo) AS maior_saldo
FROM clientes;

- GROUP BY: Agrupando Resultados

-- Número de clientes por cidade
SELECT   cidade, COUNT(*) AS qtd
FROM     clientes
GROUP BY cidade
ORDER BY qtd DESC;

- JOIN + GROUP BY: Relatórios Completos

-- Gasto total por cliente
SELECT
    c.nome,
    COUNT(pe.id)                 AS num_pedidos,
    SUM(pe.quantidade * p.preco) AS total_gasto
FROM       clientes  c
INNER JOIN pedidos   pe ON c.id = pe.cliente_id
INNER JOIN produtos  p  ON p.id = pe.produto_id
GROUP BY  c.id, c.nome
ORDER BY  total_gasto DESC;

- HAVING: Filtrando Grupos

WHERE filtra linhas antes do agrupamento. HAVING filtra grupos depois:

-- Categorias com mais de 2 produtos
SELECT   categoria, COUNT(*) AS qtd
FROM     produtos
GROUP BY categoria
HAVING   COUNT(*) > 2;
WHERE não pode usar funções de agregação
WHERE COUNT(*) > 2 gera erro — WHERE roda antes do agrupamento existir. Use sempre HAVING para filtrar com base em COUNT, SUM, AVG etc.

- Índices: Acelerando Consultas (Introdução)

Conforme uma tabela cresce para milhões de linhas, buscas por WHERE ficam lentas. Um índice é uma estrutura auxiliar que acelera a busca — parecido com o índice remissivo no final de um livro:

CREATE INDEX idx_clientes_cidade ON clientes (cidade);
Não exagere
Índices aceleram leitura, mas deixam INSERT/UPDATE um pouco mais lentos (o índice também precisa ser atualizado). Crie índices nas colunas mais usadas em WHERE, JOIN e ORDER BY — não em todas.
