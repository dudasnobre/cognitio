5. JOIN — Relacionando Tabelas

Na vida real, os dados ficam em várias tabelas. O JOIN combina linhas de duas ou mais tabelas com base em uma coluna relacionada — é um dos recursos mais poderosos do SQL.

- INNER JOIN: A Interseção

Retorna apenas as linhas onde existe correspondência nas duas tabelas.

-- Pedidos com nome do cliente e do produto
SELECT
    c.nome       AS cliente,
    p.nome       AS produto,
    pe.quantidade
FROM       pedidos   pe
INNER JOIN clientes  c  ON pe.cliente_id = c.id
INNER JOIN produtos  p  ON pe.produto_id = p.id;
Alias de tabela: pe, c, p são atalhos para os nomes longos. Torna o código muito mais legível.

- LEFT JOIN: Tudo da Esquerda

Retorna todas as linhas da tabela da esquerda, e as correspondentes da direita (ou NULL se não houver).

-- Todos os clientes, mesmo sem pedidos
SELECT c.nome, pe.id AS pedido_id
FROM      clientes c
LEFT JOIN pedidos  pe ON c.id = pe.cliente_id;

- Calculando o Valor de Cada Pedido

SELECT
    c.nome,
    p.nome                      AS produto,
    pe.quantidade * p.preco     AS total
FROM       pedidos  pe
INNER JOIN clientes c  ON pe.cliente_id = c.id
INNER JOIN produtos p  ON pe.produto_id = p.id
ORDER BY total DESC;
Atenção: Sem o ON, você cria um produto cartesiano — multiplica CADA linha de uma tabela por CADA linha da outra, gerando um resultado enorme e incorreto!

- RIGHT JOIN e FULL OUTER JOIN (Conceito)

Além do LEFT JOIN, existem duas variações que você vai encontrar em outros bancos de dados:

  • RIGHT JOIN: o espelho do LEFT JOIN — traz tudo da tabela da direita, com NULL onde não houver correspondência à esquerda.
  • FULL OUTER JOIN: traz tudo das duas tabelas, com NULL nos dois lados onde não houver correspondência.
Nem todo banco suporta os dois
O SQLite (usado nesta plataforma) não suporta RIGHT JOIN nem FULL OUTER JOIN nativamente — na prática, basta inverter a ordem das tabelas e usar LEFT JOIN para simular um RIGHT JOIN. PostgreSQL e MySQL 8+ já suportam ambos diretamente.

- Quantos Pedidos Cada Cliente Fez?

Combinar JOIN com uma função de contagem responde perguntas de negócio reais, como "quantos pedidos cada cliente tem, incluindo quem nunca comprou":

SELECT c.nome, COUNT(pe.id) AS total_pedidos
FROM      clientes c
LEFT JOIN pedidos  pe ON c.id = pe.cliente_id
GROUP BY c.id;
Exercício rápido
No terminal abaixo, use o snippet "Pedidos por cliente" e depois tente adaptar a consulta para mostrar só os clientes que nunca fizeram pedido (dica: adicione WHERE pe.id IS NULL antes do GROUP BY).

- Resumo do Módulo

  • INNER JOIN traz só as linhas com correspondência nas duas tabelas
  • LEFT JOIN traz tudo da tabela da esquerda, com NULL quando não houver par
  • Sempre use ON para definir a condição de junção — sem ele, é produto cartesiano
  • Alias de tabela (c, p, pe) tornam consultas com JOIN muito mais legíveis
