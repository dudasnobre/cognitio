10. Projeto Final: Modelando um Banco de Dados Real

Hora de juntar tudo: modelagem, SELECT, JOIN, agregações, subconsultas e integridade referencial em um desafio único — modelar e consultar um pequeno sistema de biblioteca.

- O Desafio: Sistema de Biblioteca

Pense em como você modelaria estas três tabelas relacionadas — não precisa criar de verdade, é um exercício de modelagem:

CREATE TABLE livros (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    titulo TEXT NOT NULL,
    autor TEXT,
    ano INTEGER
);

CREATE TABLE membros (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nome TEXT NOT NULL,
    email TEXT UNIQUE
);

CREATE TABLE emprestimos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    livro_id INTEGER REFERENCES livros(id),
    membro_id INTEGER REFERENCES membros(id),
    data_emprestimo TEXT,
    data_devolucao TEXT
);

- Perguntas que um Bom Modelo Precisa Responder

  • Quais livros estão emprestados no momento (sem data_devolucao preenchida)?
  • Qual membro pegou mais livros emprestados?
  • Quais livros nunca foram emprestados?

- Praticando no Banco Já Disponível

Como o laboratório abaixo usa o banco de clientes/produtos/pedidos já conhecido, pratique consultas equivalentes de "estilo relatório final", combinando tudo que você aprendeu:

-- Ranking de clientes por valor total gasto, dos maiores para os menores
SELECT
    c.nome,
    COUNT(DISTINCT pe.id)               AS total_pedidos,
    SUM(pe.quantidade * p.preco)        AS total_gasto
FROM clientes c
JOIN pedidos pe  ON c.id = pe.cliente_id
JOIN produtos p  ON p.id = pe.produto_id
GROUP BY c.id, c.nome
ORDER BY total_gasto DESC;
-- Produtos nunca vendidos (subconsulta + NOT IN)
SELECT nome, preco
FROM produtos
WHERE id NOT IN (SELECT DISTINCT produto_id FROM pedidos);
-- Cliente com maior gasto médio por pedido
SELECT c.nome, AVG(pe.quantidade * p.preco) AS gasto_medio
FROM clientes c
JOIN pedidos pe ON c.id = pe.cliente_id
JOIN produtos p ON p.id = pe.produto_id
GROUP BY c.id
ORDER BY gasto_medio DESC
LIMIT 1;
Modelar bem é 80% do trabalho
Um banco bem modelado — com chaves corretas e sem repetição desnecessária de dados — torna consultas complexas como essas muito mais simples de escrever. Tempo investido na modelagem economiza dor de cabeça depois.
