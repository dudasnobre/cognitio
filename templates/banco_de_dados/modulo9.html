9. Chaves Estrangeiras, Índices e Integridade Referencial

O que garante que um pedido não referencie um cliente que não existe? O que faz uma consulta em uma tabela com milhões de linhas continuar rápida? As respostas são chaves estrangeiras e índices.

- Chave Primária (revisão)

CREATE TABLE clientes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nome TEXT NOT NULL
);

A chave primária identifica cada linha de forma única — nunca se repete, nunca é nula.

- Chave Estrangeira (FOREIGN KEY)

CREATE TABLE pedidos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    cliente_id INTEGER REFERENCES clientes(id),
    produto_id INTEGER REFERENCES produtos(id),
    quantidade INTEGER NOT NULL
);

A chave estrangeira diz: "o valor de cliente_id aqui precisa corresponder a um id que realmente existe na tabela clientes". Isso é chamado de integridade referencial — o banco impede pedidos "órfãos", associados a clientes inexistentes.

- O que Acontece ao Excluir um Registro Referenciado?

CREATE TABLE pedidos (
    ...
    cliente_id INTEGER REFERENCES clientes(id) ON DELETE CASCADE
    -- CASCADE: exclui os pedidos junto com o cliente
    -- SET NULL: zera o cliente_id do pedido, mantendo o pedido
    -- RESTRICT: impede a exclusão do cliente enquanto houver pedidos
);

- Índices: Acelerando Consultas

CREATE INDEX idx_pedidos_cliente ON pedidos(cliente_id);
CREATE INDEX idx_clientes_email ON clientes(email);

Um índice funciona como o índice remissivo de um livro: em vez de o banco varrer linha por linha (o que é lento em tabelas grandes), ele consulta uma estrutura organizada que aponta diretamente para onde os dados estão.

  • Colunas usadas com frequência em WHERE e JOIN são boas candidatas a índice
  • Chaves primárias já são indexadas automaticamente na maioria dos bancos
  • Índices demais podem deixar operações de INSERT/UPDATE mais lentas — use com moderação

- Normalização (Conceito Básico)

Normalizar um banco significa organizar os dados para evitar repetição desnecessária. Em vez de repetir o nome do cliente em cada pedido, guardamos apenas o cliente_id e buscamos o nome na tabela clientes quando necessário — é exatamente o que o JOIN faz.

Chaves estrangeiras evitam bugs silenciosos
Sem integridade referencial, é fácil acabar com pedidos "fantasmas" apontando para clientes já excluídos — bugs difíceis de rastrear que só aparecem quando alguém tenta exibir os dados relacionados.
Índice não é solução para tudo
Criar um índice em toda coluna "só por garantia" pode piorar a performance de escrita sem ganho real de leitura. Crie índices com base em como as consultas realmente filtram e relacionam os dados.

- Resumo do Módulo

  • FOREIGN KEY garante que relacionamentos entre tabelas sejam sempre válidos
  • ON DELETE CASCADE/SET NULL/RESTRICT define o comportamento em exclusões
  • Índices aceleram buscas e joins, mas têm custo em operações de escrita
  • Normalização evita repetição de dados, mantendo relações via chaves
