7. Eventos e Fetch (APIs)

Eventos permitem que o JavaScript reaja a ações do usuário — cliques, teclas, rolagem. O Fetch permite buscar dados de APIs externas de forma assíncrona, sem recarregar a página. Juntos, são o coração das aplicações web modernas.

- Eventos com addEventListener

const btn = document.querySelector('#meu-btn');

btn.addEventListener('click', function(event) {
    console.log('Clicado!', event.target);
});

// Com arrow function
btn.addEventListener('click', e => {
    e.preventDefault(); // bloqueia comportamento padrão
    console.log('X:', e.clientX, 'Y:', e.clientY);
});

- Eventos Comuns

  • click — clique do mouse
  • input / change — digitação em campo
  • submit — envio de formulário
  • keydown / keyup — teclas pressionadas
  • mouseover / mouseout — hover
  • DOMContentLoaded — DOM pronto

- Assincronismo: Promises e async/await

Operações lentas (rede, disco) são assíncronas — o JS não espera, continua rodando. Promises e async/await gerenciam isso:

// async/await (forma moderna)
async function buscarDados() {
    try {
        const resposta = await fetch('https://api.exemplo.com/dados');
        const dados    = await resposta.json();
        console.log(dados);
    } catch (erro) {
        console.error('Erro:', erro.message);
    }
}
buscarDados();

- Fetch API

// GET — buscar dados
const res  = await fetch('https://jsonplaceholder.typicode.com/todos/1');
const todo = await res.json();
console.log(todo.title);

// POST — enviar dados
const resposta = await fetch('/api/usuarios', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ nome: 'Ana', email: 'ana@email.com' })
});
const resultado = await resposta.json();

- Event Delegation

Em vez de adicionar evento em cada filho, adicione no pai e filtre pelo alvo — muito mais eficiente:

const lista = document.querySelector('ul');

lista.addEventListener('click', e => {
    if (e.target.tagName === 'LI') {
        e.target.classList.toggle('concluido');
        console.log('Item clicado:', e.target.textContent);
    }
});
Sempre use try/catch com fetch
O fetch só lança erro em falhas de rede. Erros HTTP (404, 500) não são erros de Promise — verifique response.ok manualmente: if (!res.ok) throw new Error(res.status);

- Entendendo a Promise por Dentro

async/await é só uma forma mais legível de escrever Promises. Por baixo dos panos, toda Promise tem três estados — pending, fulfilled ou rejected — e pode ser tratada também com .then()/.catch():

fetch('https://jsonplaceholder.typicode.com/todos/1')
    .then(res => res.json())
    .then(dados => console.log(dados))
    .catch(erro => console.error('Falhou:', erro));

// É exatamente equivalente ao async/await do exemplo anterior —
// escolha o estilo que ficar mais legível para o seu time.
await só funciona dentro de função async
Usar await fora de uma função marcada com async gera SyntaxError (exceto em módulos ES com top-level await). Sempre envolva num async function.
